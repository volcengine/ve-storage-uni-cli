## 复制语义与操作决策

### 传输方向与限制

- 支持本地到本地、本地上传到 `tos://bucket/key`、远程下载及服务端远程复制。跨 Bucket 复制要求同 region，不支持自动跨地域中转；需要时明确拆成下载再上传。
- 此入口拒绝 `--storage-class`，递归列举采用 delimiter `/` 分层遍历；不支持 `--recursive-list-mode auto` 或 `flat`。

### 文件名、目录与过滤

- 不带 `--recursive` 时使用单个文件/对象作为源。远程目标为 Bucket 根或以 `/` 结尾时，会追加源文件名；提供最终文件名则使用该名称。本地目标为已存在目录或以 `/` 结尾时，也会追加源文件名。
- 本地目录或远程前缀/文件夹使用 `--recursive`，默认将其内容放入目标。`--include-parent` 必须配合 `--recursive`，用于保留源目录/前缀的最后一级名称；没有最后一级名称的根路径不能使用。仅改变源路径尾部 `/` 不会开启保留父目录行为。
- 递归源 `source/photos/` 中的 `a.jpg` 复制到远程 `.../backup/`，默认为 `backup/a.jpg`，使用 `--include-parent` 后为 `backup/photos/a.jpg`。 当前纯本地递归复制即使使用 `--include-parent` 仍按源根的相对路径放置文件；需要父目录时请直接在目标路径中写明。
- 递归 `--include`、`--exclude` 匹配相对路径（保留父目录时包含该段名称），排除优先。支持 `*`、`?`；不含这两种通配符时按子串匹配。模式须加引号防止 Shell 展开；这些过滤器不用于筛选单文件传输。

### 覆盖、恢复与性能

- 明确选择 `--overwrite-strategy`：`force` 在支持时覆盖，`no-clobber` 跳过已存在目标，`newer` 比较源和目标时间戳，并非内容相同校验。配置文件可能改变默认值。`--force` 与 `--no-clobber` 不可同时使用；优先选择一个明确策略，避免混用别名。
- `--checkpoint` 启用可恢复传输状态，`--checkpoint-dir` 指定保存位置，`--checkpoint-threshold` 控制启用 checkpoint 后使用分片/范围传输的阈值。大文件也可能自动选择分片。checkpoint 适用于上传、下载及分片远程复制；纯本地复制并非可恢复分片传输。
- 递归传输用 `--batch-concurrency` 控制项目并发、`--list-concurrency` 控制列举并发；`--multipart-concurrency` 控制单文件分片/范围并发。增加并发前检查带宽、服务限制及本地资源。

### 预览、失败报告与结果核验

- 先用 `--dry-run` 检查源、目标及计划行为。预览不证明权限、远程目标存在、远程清单完整或传输成功；留意影响范围中未知/截断字段。
- 递归操作可用 `--manifest-path` 保存计划项目、`--report-path` 保存执行结果。`--no-manifest` 禁用清单输出，与 `--manifest-path` 冲突；流式列举可能在完整枚举源之前开始传输。`--report-failures-only` 仅减少报告行，不改变汇总数量。非递归复制拒绝报告/清单参数及 batch/list 并发参数。
- 批量操作可能部分成功并返回非零退出码。重试前检查失败/跳过计数与报告；保留 checkpoint 状态及原定路径映射用于恢复，不要把跳过项目说成新复制成功。
- 用 `stat`/`ls` 检查解析后的目标名称和大小。完整性要求较高时使用合适的校验和，或下载后计算摘要；时间戳和 ETag 不能普遍当作内容校验和。
