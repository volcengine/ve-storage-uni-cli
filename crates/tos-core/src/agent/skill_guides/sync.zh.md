## 同步决策

- 这是以源为准的单向操作，并非双向冲突合并。执行前检查源/目标方向、递归相对路径、`--include-parent` 及包含/排除过滤器。
- 不带 `--delete` 时保留目标独有项目；`--delete` 开启目标清理并提高确认要求，启用前用 `--dry-run` 检查准确目标范围。预览可能未完成发现，不能证明已列出全部待删除项目。
- 已有文件需要保护时明确选择 `--overwrite-strategy`。`newer` 比较时间戳，不做逐字节校验；实际配置与后端共同决定传输行为。
- 传输失败会阻止后续目标清理阶段。部分成功后可能同时存在已复制项目与保留的多余项目，重试前检查汇总及报告。
- `--report-path` 保留结果，`--manifest-path` 保留计划项目；`--no-manifest` 改用流式发现并放弃完整清单输出。核验目标应有项目、失败数量，以及仅在授权 `--delete` 时检查目标多余项目的清理结果。
