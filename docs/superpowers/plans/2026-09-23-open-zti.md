# Open source ByteTOS ZTI implementation plan

> This replaces Commit 4 in `2026-09-22-tos-zti-auth.md`. The user approved
> implementing only the ZTI capabilities needed by this CLI inside the public
> repository, following the existing SD lookup pattern. Finish and review one
> local commit, then stop for user review before subsequent skill/help work.

**Goal:** A public `tos --auth-mode zti` build works without a private Cargo
registry. `ve-tos` and `ve-adrive` continue to reject ZTI.

**Architecture:** Keep the existing `ZtiTokenProvider` abstraction, request
header path, and auth-mode configuration. Replace `internal/tos-zti-cli` with a
public provider in `tos-core`. Discover `SEC_TOKEN_STRING`, then an existing
`ZTI_AGENT_SOCKET_PATH` or default Agent socket, then existing
`SEC_TOKEN_PATH`. Selection is once per invocation; errors never fall back to
a lower-priority source. Each HTTP attempt asks the provider for the current
Token. Environment strings are static; files are read on each attempt; Agent
Tokens are cached until the earlier of ten minutes or ten seconds before JWT
expiry, then fetched again. All reads and RPCs have a ten-second deadline.

**Public protocol:** Implement the single standard SPIFFE Workload API method
`FetchJWTSVID` with audience `zti` using public tonic/prost dependencies and a
Unix socket. Define only the three protobuf messages needed for that method;
keep the token out of Debug/log/error output. JWT payload parsing only checks
format, SPIFFE-shaped subject, and expiration; it does not verify the signature.
ByteTOS verifies service-side identity and permissions. No Token exchange for
AK/SK. On non-Unix platforms, environment/file sources remain supported; Agent
source selection explicitly reports unavailable if configured.

**Security:** Reject empty/malformed/expired Tokens and values too large for
an HTTP header. File reads are bounded, and no raw Token or SDK error is
logged. The public implementation has no background refresh task, so cancellation
cannot leave orphaned tasks or trigger upstream SDK Token-printing panic paths.
Direct file re-read avoids the macOS notifier mismatch from SDK 0.1.9.

**Execution (one reviewable commit):**

- [x] Add public protocol client and local Unix gRPC mock tests.
- [x] Add public source selection, JWT expiry checks, bounded file reads,
      Agent cache/deadline behavior, and TDD unit tests.
- [x] Auto-inject the public provider in unified and direct `tos` entry paths;
      retain explicit provider injection API for tests/embedders.
- [x] Replace private integration tests with public CLI tests for env/file,
      refresh, failures, normal request, MCP child, and TRACE redaction.
- [x] Remove `internal/tos-zti-cli` and its private lock/registry configuration.
- [x] Validate public metadata/package closure, macOS tests, Linux build,
      formatting, and full Review.
- [ ] Validate Windows build with a Windows C toolchain; the local macOS cross
      check stops in pre-existing `ring` C code because Windows headers are absent.
- [x] Commit locally and stop for user review.

**Verification:** 12 focused CLI tests, 195 `tos-core` unit tests, eight
`tos-cli-core` unit tests, and 14 root library tests passed. A public Linux
x86-64 executable built with Zig. Cargo metadata resolved 341 crates with no
private registry source, and the `tos-core` package list includes all three ZTI
source files. No real Agent or ByteTOS service was contacted.
